## 📌 What This Project Is

**xtra.me-pro** is a **team project-planning SaaS backend** with an embedded AI assistant called **AXEL**.

It is a **FastAPI** Python app that:
- Manages orgs, members, idea pitches, and projects
- Lets pitches be converted into structured projects with steps/substeps
- Has an AI chat layer (AXEL) powered by Groq LLM for personal work planning
- Sends scheduled morning & check-in emails to users via Resend
- Uses **Supabase** as the database + auth layer

## 🔁 Core Execution Flow

### 1. API Request Auth
Every protected endpoint requires **two** auth headers:
- `x-api-key: <BACKEND_API_KEY>` (static secret — `Depends(check_key)`)
- `Authorization: Bearer <supabase_jwt>` (user session — `Depends(get_user_id)`)

### 2. Org → Pitch → Project Pipeline
```
POST /orgs              → creates org, auto-adds creator as "owner"
POST /pitches           → submits idea pitch inside an org
POST /pitches/{id}/messages → discussion thread on a pitch
POST /pitches/{id}/convert  → converts pitch to a full project
  └─ inserts into: projects, project_steps, project_substeps
  └─ archives the pitch (status="archived")
```

### 3. Project Management
```
GET  /orgs/{id}/projects          → list all org projects with steps
POST /assignments                 → assign org_member to project or step
GET  /projects/{id}/assignees     → list assignees
PATCH /steps/{id}                 → update step priority/status/due_date
PATCH /substeps/{id}              → toggle substep checkbox
POST /delays                      → log a delay report for a step
```

### 4. AI Layer (AXEL)
```
POST /chat              → user sends message → AXEL replies with project context
POST /daily-brief       → triggers AXEL to summarize today's priorities for user
```
- `get_member_context()` in `main.py` fetches: member info, their assignments, availability overrides, and all org projects.
- Both chat and daily-brief persist messages to `ai_messages` table.
- AXEL's personality: warm but efficient, never acts without user confirmation on reassignment/notifications.

### 5. Scheduled Email Jobs
```
POST /jobs/morning-email  → triggered by cron-job.org → email_job.run("morning")
POST /jobs/daytime-email  → triggered by cron-job.org → email_job.run("daytime")
```
- Skips users who are **active on the site within 3 hours** (`last_seen` column)
- Skips users with no `groq_api_key` stored in `org_members`
- Emails are sent via Resend, generated by Groq LLM

## 💡 Known Design Decisions & Ideas

See `DB_SCHEMA.md` for table details.

| # | Decision / Idea | Status |
|---|---|---|
| 1 | groq_api_key stored per org_member (user brings own key) | ✅ Current |
